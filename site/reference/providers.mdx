Every provider whose per-environment state Sponson manages, by category: what it manages, the op or recipe that
does it, the credential it reads from the environment (where to create it, and what to pick: `sponson init --setup` walks
through the same), what `sponson init` detects it by, and a line to start from.
`sponson init` reads dependency names, config files and variable names (never their values) and writes these lines
for every provider it detects: ready to apply when it knows every value, else commented out with a `# TODO:` that
says where to find each missing one.

59 providers in 11 categories: 15 ops of first-class adapters and 63 recipe ops, plus 3 steps no API reaches, tracked as [`manual.step`](/reference/plan-format#manual-step) lines. `sponson init` detects 55 providers.

- First-class ops: [the plan format](/reference/plan-format#built-in-ops). Recipes: [Recipes](/reference/recipes).
- What is covered and what is not, and why: [Provider coverage](/reference/coverage).
- A provider that is missing: add a recipe (one YAML file; its `detect` block makes `sponson init` find it), see
  [CONTRIBUTING.md](/contributing/contributing).

### Vercel

Env vars per target and git branch; wait for the preview deployment, redeploy if it built before the write.

- **Ops**: [`vercel.env`](/reference/plan-format#vercel-env), [`vercel.deploy`](/reference/plan-format#vercel-deploy)
- **Credential**: `VERCEL_TOKEN`
- **Token**: [create it](https://vercel.com/account/tokens): A token whose Scope is the team that owns the project, with an expiration. `sponson init --setup` checks it with one read-only request.
- **Detected by `sponson init` from**: `vercel`, `@vercel/*`, `vercel.json`, `.vercel/project.json`, `VERCEL_*`

```yaml
# from examples/clerk-preview-callbacks.plan.yaml
providers:
  vercel: { project: prj_acme_web }
changes:
  - id: env
    adapter: vercel
    op: env
    target: preview
    values:
      DATABASE_URL: { from: db.connection_string }
      CLERK_SECRET_KEY: { secret: env://CLERK_PREVIEW_SECRET_KEY }
    environments: [preview]
```

### Cloudflare Pages / Workers

Pages: `deployment_configs.preview.env_vars` (all previews share one set, no per-branch values). Workers: secrets per script / preview version (Pages variables; Workers secrets are not covered).

- **Ops**: [`cloudflare.pages_env`](/reference/plan-format#cloudflare-pages_env)
- **Credential**: `CLOUDFLARE_API_TOKEN`
- **Token**: [create it](https://dash.cloudflare.com/profile/api-tokens): A custom token with Account > Cloudflare Pages > Edit, limited to the one account. `sponson init --setup` checks it with one read-only request.
- **Detected by `sponson init` from**: `wrangler`, `@cloudflare/next-on-pages`, `wrangler.json`, `wrangler.jsonc`, `wrangler.toml`, `CLOUDFLARE_*`

```yaml
# from examples/cloudflare-pages-vars.plan.yaml
providers:
  cloudflare: { account: 0123456789abcdef0123456789abcdef, project: acme-web }
changes:
  - id: pages-preview
    adapter: cloudflare
    op: pages_env
    vars: { PUBLIC_API_URL: https://api.staging.acme.dev, PUBLIC_STAGE: preview }
    secrets:
      STRIPE_SECRET_KEY: { secret: env://STRIPE_TEST_SECRET_KEY }
    environments: [preview]
```

### Render

Env vars on a preview service / preview environment (per variable on a service whose id the plan gives (Render creates previews itself; no lookup of PR N's service); writing does not deploy).

- **Ops**: recipe [`render.env_var`](/reference/recipes#render-env_var)
- **Credential**: `RENDER_API_KEY` (bearer)
- **Token**: [create it](https://dashboard.render.com/u/settings?add-api-key): An API key; Render keys have no scopes and reach every workspace of the user who creates them. `sponson init --setup` checks it with `GET /owners`.
- **Detected by `sponson init` from**: `render.yaml`, `RENDER_*`

```yaml
# under changes: (no provider block needed)
- id: env_var
  adapter: http
  op: resource
  recipe: render.env_var
  service_id: srv-d0a1b2c3d4e5f6g7h8i9
  key: API_URL
  value: https://api-${ctx.scope}.example.com
```

### Railway

Variables in a PR environment (Railway creates PR environments natively) (the PR environment's id is a param; Sponson does not wait for the redeploy a write triggers).

- **Ops**: recipe [`railway.variable`](/reference/recipes#railway-variable)
- **Credential**: `RAILWAY_API_TOKEN` (bearer)
- **Token**: [create it](https://railway.com/account/tokens): A workspace token for the workspace that holds the project. `sponson init --setup` cannot check it (no read-only request every such credential may send).
- **Detected by `sponson init` from**: `railway.json`, `railway.toml`, `RAILWAY_*`

```yaml
# under changes: (no provider block needed)
- id: variable
  adapter: http
  op: resource
  recipe: railway.variable
  project_id: prj-railway-demo
  environment_id: env-pr-42
  service_id: svc-web
  name: API_URL
  value: https://api-${ctx.scope}.example.app
```

### Fly.io

Per-PR app (the usual pattern is one app per PR) plus its secrets (secrets before the PR's deploy; a later change needs `fly secrets deploy`).

- **Ops**: recipe [`fly_machines.app`](/reference/recipes#fly_machines-app), recipe [`fly.secret`](/reference/recipes#fly-secret)
- **Credential**: `FLY_API_TOKEN` (bearer)
- **Token**: [create it](https://fly.io/dashboard): An org token (`fly tokens create org`): it creates and deletes apps in the organization. `sponson init --setup` cannot check it (no read-only request every such credential may send).
- **Token**: [create it](https://fly.io/dashboard): A deploy token for the one app (`fly tokens create deploy -a <app>`), or an org token (`fly tokens create org`) for an app per PR. `sponson init --setup` cannot check it (no read-only request every such credential may send).
- **Detected by `sponson init` from**: `fly.toml`, `FLY_*`

```yaml
# under changes: (no provider block needed)
- id: app
  adapter: http
  op: resource
  recipe: fly_machines.app
  app_name: demo-${ctx.scope}
  org_slug: acme
```

### Heroku

Review app per PR; config vars on it (config vars on an existing app (a review app by name); creating the review app (async, by Heroku's automatic review apps) is not managed).

- **Ops**: recipe [`heroku.config_var`](/reference/recipes#heroku-config_var)
- **Credential**: `HEROKU_API_KEY` (bearer)
- **Token**: [create it](https://dashboard.heroku.com/account/applications): A long-lived authorization from `heroku authorizations:create -s write-protected`: the narrowest scope that reads and writes config vars. `sponson init --setup` cannot check it (no read-only request every such credential may send).
- **Detected by `sponson init` from**: `heroku.yml`, `HEROKU_*`

```yaml
# under changes: (no provider block needed)
- id: config_var
  adapter: http
  op: list_item
  recipe: heroku.config_var
  app: myapp-${ctx.scope}
  key: API_URL
  value: https://api-${ctx.scope}.example.com
```

### AWS Amplify

Branch (per-PR previews built in); env vars per branch (variables before the branch's first build (no rebuild)).

- **Ops**: recipe [`amplify.branch`](/reference/recipes#amplify-branch), recipe [`amplify.branch_variable`](/reference/recipes#amplify-branch_variable)
- **Credential**: `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` (AWS SigV4, `amplify` in `us-east-1`)
- **Token**: [create it](https://console.aws.amazon.com/iam/home#/users): An IAM user's access key whose policy allows amplify:ListApps, amplify:GetBranch, amplify:CreateBranch, amplify:UpdateBranch and amplify:DeleteBranch on the app. `sponson init --setup` checks it with `GET /apps`.
- **Detected by `sponson init` from**: `amplify.yml`

```yaml
# under changes: (no provider block needed)
- id: branch
  adapter: http
  op: resource
  recipe: amplify.branch
  app_id: d1demo
  branch_name: ${ctx.scope}
  stage: PULL_REQUEST
  description: Preview of ${ctx.scope}
```

### Google Cloud Run

Tagged revision per PR (`--tag pr-42`), env vars on it (a revision of an existing service per scope from its template, with the plan's image and variables, tagged and given no traffic (traffic on LATEST is pinned only with the line's `pin_latest: true`, refused otherwise); destroy removes the tag and Cloud Run deletes the revision later).

- **Ops**: [`cloud_run.revision`](/reference/plan-format#cloud_run-revision)
- **Credential**: the token `gcloud auth print-access-token` prints (bearer)
- **Token**: [set up access](https://console.cloud.google.com/iam-admin/iam): Sign in with `gcloud auth login` as an identity holding Cloud Run Developer (roles/run.developer) and Service Account User on the service's runtime service account. `sponson init --setup` shows this; there is no token to store.
- **Detected by `sponson init` from**: `@google-cloud/run`, `CLOUD_RUN_*`, `K_SERVICE`

```yaml
# from examples/cloud-run-neon-preview.plan.yaml
providers:
  cloud_run: { project: acme-web-prod, region: europe-west1 }
changes:
  - id: preview
    adapter: cloud_run
    op: revision
    service: web
    image: europe-west1-docker.pkg.dev/acme-web-prod/web/app:${ctx.git.sha}
    env:
      DATABASE_URL: { from: db.connection_string }
      SESSION_SECRET: { secret: env://PREVIEW_SESSION_SECRET }
      APP_ENV: preview
    environments: [preview]
```

### Azure Static Web Apps

Preview environment per PR (built in); app settings (after the PR's first deploy (the environment exists only then)).

- **Ops**: recipe [`azure_swa.build_app_setting`](/reference/recipes#azure_swa-build_app_setting)
- **Credential**: the token `az account get-access-token --query accessToken -o tsv` prints (bearer)
- **Token**: [set up access](https://learn.microsoft.com/en-us/azure/role-based-access-control/built-in-roles): Sign in with `az login` as an identity holding Contributor on the static web app (or a custom role with Microsoft.Web/staticSites/*). `sponson init --setup` shows this; there is no token to store.

```yaml
# under changes: (no provider block needed)
- id: build_app_setting
  adapter: http
  op: list_item
  recipe: azure_swa.build_app_setting
  subscription_id: 00000000-0000-0000-0000-000000000000
  resource_group: rg-web

  environment: "42"

```

### DigitalOcean App Platform

No native PR previews; app per PR via its GitHub action; envs in the app spec (an app per scope from a whole spec, waited for until deployed (in place of the app DigitalOcean's GitHub action makes); secret values are not compared).

- **Ops**: [`digitalocean.app`](/reference/plan-format#digitalocean-app)
- **Credential**: `DIGITALOCEAN_ACCESS_TOKEN`
- **Token**: [create it](https://cloud.digitalocean.com/account/api/tokens): A personal access token with Custom Scopes: app:read and app:update. `sponson init --setup` checks it with one read-only request.

```yaml
# from scenarios/adapters/digitalocean.yaml

    adapter: digitalocean

      name: web-${ctx.scope}

        - name: web

```

R2: an API token with Admin Read & Write. `sponson init --setup` cannot check it (no read-only request every such credential may send).
- **Detected by `sponson init` from**: `@aws-sdk/client-s3`

```yaml
providers:
  http:
    s3:
      recipe: s3
      base_url: https://assets.s3.us-east-1.amazonaws.com
changes:
  - id: bucket_cors
    adapter: http
    op: list_item
    recipe: s3.bucket_cors
    rule_id: sponson-${ctx.scope}
    origin: https://${ctx.scope}.preview.example.app
```

### Upstash Redis

Database per PR, REST URL and token out.

- **Token**: [create it](https://console.upstash.com/account/api): A Developer API key (Account > Developer API) with Read/Write; the account's email is its user name. `sponson init --setup` checks it with `GET /redis/databases`.
- **Detected by `sponson init` from**: `@upstash/redis`, `UPSTASH_REDIS_*`

```yaml
# under changes: (no provider block needed)

```

### Upstash QStash

Schedule that calls the preview URL.

- **Ops**: recipe [`qstash.schedule`](/reference/recipes#qstash-schedule)
- **Credential**: `QSTASH_TOKEN` (bearer)
- **Token**: [create it](https://console.upstash.com/qstash): The QStash token of the region (QStash tab); it has no scopes. `sponson init --setup` checks it with `GET /v2/schedules`.
- **Detected by `sponson init` from**: `@upstash/qstash`, `QSTASH_*`

```yaml
# under changes: (no provider block needed)
- id: schedule
  adapter: http
  op: resource
  recipe: qstash.schedule

  destination: https://${ctx.scope}.preview.example.com/api/cron

```

### Inngest

Sync the preview deployment into its branch environment (an `http.action` (ADR 0022): `PUT` to the deployment's serve endpoint once per deployment URL and revision, no Inngest credential; the app must set `INNGEST_ENV` (automatic on Vercel); nothing to undo (branch environments archive themselves); the beta REST v2 sync endpoint is not used (no way to target a branch environment)).

- **Ops**: recipe [`inngest.sync`](/reference/recipes#inngest-sync)
- **Credential**: none of Sponson's (calls a URL the line gives; a key it needs is a `{ secret }` param)
- **Detected by `sponson init` from**: `inngest`, `INNGEST_*`

```yaml
# under changes: (no provider block needed)
- id: sync
  adapter: http
  op: action
  recipe: inngest.sync
  url: https://acme-git-feat-x-acme.vercel.app
  revision: ${ctx.git.sha}
```

### Algolia

Index per environment, copied from a template index (copies records, settings, synonyms and rules (or a scope of them) and waits for the copy task; only the index's existence is compared for drift).

- **Ops**: [`algolia.index`](/reference/plan-format#algolia-index)
- **Credential**: `ALGOLIA_API_KEY`
- **Token**: [create it](https://dashboard.algolia.com/account/api-keys/): A restricted API key (not the Admin key) with the addObject, deleteIndex, editSettings, settings and listIndexes ACLs. `sponson init --setup` checks it with one read-only request.
- **Detected by `sponson init` from**: `algoliasearch`, `@algolia/*`, `instantsearch.js`, `react-instantsearch`, `ALGOLIA_*`

```yaml
# from scenarios/adapters/algolia.yaml
providers:

changes:

    adapter: algolia
    op: index
    name: products_${ctx.scope}
```

### Stripe sandboxes

A sandbox per PR.

- **Ops**: [`manual.step`](/reference/plan-format#manual-step)
- **Credential**: none (a person does it)
- **Detected by `sponson init` from**: not detected (write the line yourself)

```yaml
# from examples/google-oauth-manual-step.plan.yaml
changes:
  - id: google-redirect
    adapter: manual
    op: step
    title: Allow ${ctx.scope}'s OAuth callback on the Google OAuth client acme-web
    vars:
      url: { from: env.preview_url }
    instructions: |
      Google offers no API for a web client's redirect URIs, so this is done by hand.

      1. Open https://console.cloud.google.com/apis/credentials (project `acme-web`).
      2. Open the OAuth 2.0 client **acme-web**.
      3. Under **Authorized redirect URIs**, add `{url}/api/auth/callback/google`.
      4. Save. Google may take a few minutes to accept the new URI.
    undo: |
      In the same client, remove `{url}/api/auth/callback/google` from **Authorized redirect URIs**, and save.
    environments: [preview]
```
